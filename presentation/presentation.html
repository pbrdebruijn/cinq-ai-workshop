Part 1

Principles &
workflow

Habits that outlive the changelog — then two tool shapes

Durable principles

These apply to autocomplete, chat, and full agents alike

  • Context is the product — files, errors, constraints beat “fix my app”
  • Verify, don’t trust — tests, diffs, reproduction before big merges
  • Bound the work — small steps, clear done; fresh session for unrelated tasks
  • Encode once — repo rules beat repeating the same lecture in chat

Agentic coding

More delegation — plans, multi-file edits, shell commands — more upside and more risk.

  • Calibrate trust — explain-first or narrow scope first; widen as CLAUDE.md / rules mature
  • Guardrails stack — project instructions, review before merge, undo/checkpoints, sandbox or allowlists where you have them
  • MCP & integrations — only with org approval; same hygiene as any production access
  • You own secrets and prod — automation assists; responsibility stays human

PR review bots, debug-with-evidence, bounded bash — same theme: evidence + boundaries, not autopilot.

Tools move fast

Both Cursor and Claude Code ship constantly — this deck is a snapshot. Official docs are the real changelog.

  • Bookmark docs.cursor.com and Claude / Claude Code docs for follow-up
  • Examples of the principles above (not a shopping list): plugins bundling rules & MCP; automated PR review; gathering runtime evidence before patching; checkpoints / rewind

Skip quarterly timeline slides — use release notes when you need “what’s new.”

Cursor

In-editor, diff-forward — VS Code lineage; AI next to the code you see.

  • Tab — multi-line completion
  • Cmd+K — inline edit with natural language
  • Composer — multi-file changes with visible context
  • Chat + @ — codebase-aware; pull files & symbols into the thread

Reach for it when you want a tight loop and to read every diff in the editor.

Claude Code

Terminal-first agent — editor-agnostic; drive the repo from a pane.

  • Autonomy — file edits + shell commands in one flow
  • Exploration — multi-step tasks across the tree
  • Git-native — commits, branches, PRs as first-class
  • Repeatability — CLAUDE.md, slash commands, skills

Reach for it for repo-wide or scripted work; optional IDE extension for inline diffs where you use it.

When to use which?

Scenarios, not absolutes — same developer, different tasks

Cursor (in-editor) Claude Code (CLI agent)
Tight edits, Tab, small surfaces Large refactors, scaffolding, many files
You want the diff in the IDE You live in the terminal or want one agent pane
Autocomplete + chat beside the file Multi-step plans, commands, git operations
Polish after a big change Big moves, then hand off to the editor

.cursorrules & plugins (Cursor) · CLAUDE.md & slash commands (Claude Code). They complement — e.g. agent for bulk work, Cursor for refinement.

Part 3

Best Practices

Tips for effective AI-assisted coding

Context Management

Bad: “Fix the login bug”

Good: “In src/auth/validate.ts, JWT validation fails when tokens contain special characters. Error on line 45.”

  • Reference files explicitly — use @-mentions or paths
  • Chunk large tasks — smaller, verifiable steps
  • Fresh context — new session for unrelated tasks

Prompting Techniques

1. Goal first, then constraints

"Build a user registration form.
Constraints: react-hook-form, zod validation,
no external UI libraries."

2. Provide examples

"Format output like: { id: string, name: string }"

3. Ask for explanation first

4. Iterate, don’t restart

Project configuration

Versionable team guardrails — not personal superstitions

.cursorrules

You are working on Next.js 14:
- App Router (not Pages)
- TypeScript strict mode
- Tailwind CSS

Rules:
- No 'use client' unless needed
- Use named exports
- Prefer Server Actions

CLAUDE.md

# Project: Dashboard

## Stack
- Next.js 14, TypeScript
- Prisma + PostgreSQL

## Don't
- Don't use `any` type
- Don't install deps without asking

MCP — Model Context Protocol

Connect AI to external tools and data

  • Database Access — Query Postgres directly
  • Documentation — Fetch from Notion, Confluence
  • Design Tools — Pull from Figma
  • Custom Tools — Internal APIs, services

Keep it simple: most projects don’t need MCP. Start without it.

Part 4

Open
Assignment

45 minutes — your own project

Open Assignment

Work on your own project or idea

Ideas if stuck:

  • Port a side project feature to a new framework
  • Build a tool that solves a daily annoyance
  • Recreate a simple app (Trello board, Pomodoro timer)
  • Prototype an idea you’ve been thinking about

Tips for success

  1. Start with a clear, written goal
  2. Use plan mode / Composer / agent for scaffolding — then verify
  3. Iterate in smaller chunks; pairing helps (one prompts, one reads diffs)
  4. Restart context if stuck — long threads accumulate noise
